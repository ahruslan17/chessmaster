# Проверка frontend

Нужны Node.js 20+ и уже подготовленный `frontend/node_modules`. Команды выполняются из корня репозитория; установки зависимостей, сервер, БД и LLM для этих проверок не нужны. Если зависимости отсутствуют, используйте подготовленную копию проекта, не запускайте установку автоматически.

## Сборка

```bash
npm --prefix frontend run build
```

Команда запускает TypeScript и Vite; создаёт артефакты сборки. Для проверки без записей в рабочую копию выполняйте её в отдельной подготовленной копии с существующими зависимостями.

## Core-тесты без framework и сети

```bash
(
  set -eu
  check_dir="$(mktemp -d "${TMPDIR:-/tmp}/chessmaster-core.XXXXXX")"
  printf '{"type":"commonjs"}\n' > "$check_dir/package.json"
  node frontend/node_modules/typescript/bin/tsc \
    frontend/src/api/client.ts frontend/src/engineScore.ts \
    --module commonjs --moduleResolution node --target ES2022 \
    --lib ES2022,DOM --strict --skipLibCheck --outDir "$check_dir"
  node frontend/test-core.mjs "$check_dir"
  printf 'Артефакты проверки: %s\n' "$check_dir"
)
```

Импорты компилируют также `api/sse.ts` и типы. Отдельный `package.json` нужен, чтобы Node читал результат как CommonJS независимо от ESM-настроек frontend. Скрипт подменяет `fetch`: настоящих HTTP-запросов и генерации нет. Успех — строка `PASS: SSE ...` и код выхода 0; ошибка assertion даёт ненулевой код.

Покрытие:
- SSE: все позиции разреза сообщения на два chunk, посимвольная подача, CR/LF/CRLF, multiline, `data:` без пробела и с одним служебным пробелом, пустые и whitespace-only данные, конечные пробелы, EOF без разделителя;
- UTF-8: разрезы по одному байту, сброс `TextDecoder` на EOF с незавершённым символом;
- оценки: cp ±1500 не превращаются в мат; signed mate, mate=0 с победителем; неизвестная legacy-оценка не становится проверенным нулём;
- API: side-query, явные POST, recovery с `expected_attempt_id`, цвет в query/form загрузки, ответы 409 и read-only 404 комментария.

## Ручной browser smoke

Используйте уже запущенный разрешённый тестовый стенд и сохранённые партии. Не запускайте новый runtime или платный LLM ради smoke. Для проверки очереди/ошибок подходят подготовленные fixtures или перехваченные ответы. В DevTools включите Network → Preserve log.

1. **Размеры 360/390/768/1440 CSS px.** На каждом размере откройте библиотеку и viewer, измените ширину без reload. Доска квадратная, помещается в контейнер и пересчитывается через ResizeObserver; на мобильном панели расположены вертикально, header и кнопки переносятся. Нет горизонтального overflow страницы; широкая таблица прокручивается внутри контейнера. Проверьте доступность кнопок с клавиатуры и видимый focus.
2. **Только чтение при навигации.** Откройте партию, reload, выберите ход, включите autoplay, поверните доску, смените сторону и вернитесь из библиотеки. В Network допустимы GET анализа/статуса; POST `/analysis/start` и `/analysis/explanations` не появляются. Нет автоматического запроса commentary stream. Отсутствующий сохранённый комментарий не запускает генерацию.
3. **Состояния библиотеки.** Заблокируйте GET `/api/games` через DevTools и дождитесь ошибки: показываются ошибка и retry, а не пустая библиотека. Снимите блокировку, нажмите повтор — список восстановлен. Отдельно проверьте загрузку, действительно пустой список и отсутствие совпадений по фильтрам.
4. **Стороны и cache.** Для партии с различимыми объяснениями white/black переключите white → black → white. Query содержит выбранный `player_color`; чужие summary/comments не мелькают. Подмените сохранённый ответ, уйдите и вернитесь: повторный mount перечитывает данные (`staleTime: 0`, `refetchOnMount: "always"`). Выбор стороны не меняет ориентацию и не отправляет POST. У партии без цвета доступны ходы, но coach требует выбора стороны; legacy-тексты скрыты.
5. **Смена маршрута.** В партии A выберите поздний ход, сторону, поворот и вариант; перейдите к партии B. Viewer remount сбрасывает локальный выбор, autoplay и вариант; ходы, оценки и комментарии A не остаются. Возврат к A перечитывает сохранённый анализ без генерации.
6. **Варианты для всех ходов.** Выберите ход своей и противоположной стороны, включая ход вне подборки ошибок. Под ветками с сохранёнными проверенными линиями есть разные кнопки «Показать последствия хода» и «Показать линию рекомендации». Проверяйте `played_line` и `best_line`; отсутствие `best_line` нельзя заменять произвольной линией из `top_moves`. Кнопка сразу показывает первый полуход, а не исходную позицию; фокус переходит в контекст линии и прокручивает его в мобильный viewport. В панели «Линия движка» каждый пронумерованный ход кликабелен; «До хода» показывает позицию перед выбранным ходом. Кнопки под доской и клавиши ←/→/Home/End управляют открытой линией, автоплей остаётся внутри неё. При листании фокус не сбрасывается; на явном возврате он возвращается к исходной кнопке ветки, при её отсутствии — к стабильной кнопке управления доской. В select, текстовом поле и модальной справке клавиши не перехватываются. Короткий постоянный polite live-status сообщает номер и SAN текущего хода партии/варианта, не перечитывая весь комментарий. Подсветка показывает последний ход линии; значок и оценка хода партии скрыты. На краях навигация блокируется. Возврат восстанавливает выбранный ход партии; выбор другого хода или стороны закрывает линию и останавливает автоплей. Комментарий помечен как относящийся к ходу партии. Пустая линия не предлагает кнопку; некорректная или начинающаяся с другого хода показывает ошибку. При совпадении ходов доступна одна ветка. Все действия дают 0 POST и 0 LLM-вызовов.
7. **Статусы и явные действия.** На fixtures проверьте pending/queued/in_progress/done/partial/failed: короткий статус подготовки, engine-only, сохранённые частичные результаты, ошибки чтения и запуска. Полностью готовый разбор не показывает служебную панель и кнопки генерации. Один запуск «Разобрать партию» всегда запрашивает оба объяснения с `detailed: true`; отдельных режимов обычного/подробного разбора, финансового текста и второго confirm нет. При реальном сбое доступна «Повторить попытку». Ошибка чтения предлагает «Повторить загрузку», запуск до загрузки данных недоступен. Технические ошибки и ручное восстановление доступны только в закрытом по умолчанию блоке «Диагностика и восстановление». Обычный запуск не содержит `recover: true`. Recovery требует подтверждения и передаёт UUID именно увиденной попытки; отмена не отправляет POST, устаревший UUID даёт 409 и обновление данных. Не проверяйте генерацию реальным LLM без отдельного разрешения.
8. **Дневник и оценки.** Нет accuracy-метрик и старых непроверенных рекомендаций. Неизвестная оценка отображается как `—`; большой cp не подписан матом. Для mate=0 победитель соответствует `mate_winner`, поворот доски не меняет смысл оценки.
9. **Объяснения и доступность.** На desktop объяснение расположено рядом с доской; на телефоне — сразу после доски и навигации, перед списком ходов. Объяснения используют системный шрифт, нотация — моноширинный. Выбранный ход имеет `aria-current="step"` и имя с номером, цветом и нотацией; список прокручивается к нему без прокрутки страницы. Проверьте светлую и тёмную темы. «Как читать оценку» открывает модальную справку: фокус на «Закрыть», Tab остаётся внутри, Escape закрывает и возвращает фокус на вызвавшую кнопку. Закрытая справка не попадает в Tab-порядок. Проверьте длинную формулу на телефоне без горизонтального overflow.
10. **Подробный формат v2.** Перехватите GET анализа: добавьте `commentary: { version: 2, played: { idea, pros, cons, tactics, plan, opponent_reply, missed_opportunity }, alternative: { idea, pros, cons }, comparison }` к выбранному ходу. Заголовок «Разбор хода»; отдельные h3 «Сыграно в партии» и «Рекомендация движка» с номером и SAN. Классификация и теория относятся только к сыгранному ходу. Идея заметнее дополнительных полей; поля представлены семантическим dl без отдельных карточек. `null`, пустые и whitespace-only поля не оставляют подписей. Сравнение отдельно внизу. При совпадении SAN видна подпись «Совпадает с рекомендацией движка» и только одно объяснение, даже если fixture содержит alternative/comparison. При `classification: best` и разных SAN панель пишет «Один из лучших», не объявляя рекомендацию обязательно лучшей. Отсутствующий SAN рекомендации не создаёт пустую ветку. Длинные абзацы и неразрывные строки помещаются на 360 px и при zoom 200%.
11. **Сохранённые legacy-комментарии.** Старые тексты доступны без эвристического разбиения. Отдельной кнопки «Добавить подробный разбор» нет: это тот же обычный разбор партии. Старый абзац не означает, что объяснение рекомендации готово. У рекомендации без текста явно показано, что объяснение готовится либо разбор не завершён. Единственный старт/повтор проверяйте ТОЛЬКО на перехваченном POST: `detailed: true`, без второго confirm, без повторного Stockfish. Во время подготовки предыдущие комментарии остаются видны. Навигация, reload и смена стороны не создают платных повторов. После готовности обе ветки показываются сразу без дополнительных действий.

Core-тесты не заменяют browser smoke и проверку backend на отсутствие побочных эффектов GET. В отчёте фиксируйте реально проверенные размеры/сценарии, ошибки console/network и ограничения стенда.

## Структурированные объяснения без браузера

`test-commentary.mjs` проверяет серверный рендер существующими React/ReactDOM: разделение веток, отсутствие пустых разделов, один блок при совпадении ходов, сохранность старого абзаца и пустые состояния. Сеть и LLM не нужны.

```bash
check_dir="$(mktemp -d /tmp/opencode/chessmaster-commentary.XXXXXX)"
printf '{"type":"commonjs"}\n' > "$check_dir/package.json"
node frontend/node_modules/typescript/bin/tsc \
  frontend/src/components/CommentaryPanel.tsx \
  --module commonjs --moduleResolution node --target ES2022 --jsx react-jsx \
  --lib ES2022,DOM --strict --skipLibCheck --outDir "$check_dir"
NODE_PATH="$PWD/frontend/node_modules" node frontend/test-commentary.mjs "$check_dir"
```
